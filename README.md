# resign-proxy

Персональный TLS-прокси, который перевыпускает сертификаты Минцифры под ваш собственный корневой CA для доменов из белого списка.

**Зачем:** корневой сертификат Минцифры устанавливать небезопасно — они технически могут выпустить сертификат для любого домена (Telegram, банки, почта) и провести MITM. Этот прокси позволяет использовать только ваш собственный CA, а Минцифры — только для явно разрешённых доменов.

**Как работает:**

```
Браузер → Прокси → upstream
                     │
    домен в whitelist? ──НЕТ──→ прозрачный TCP-туннель (Минцифры не трогаем)
          │
         ДА
          │
    сертификат от Минцифры? ──НЕТ──→ туннель (обычный CA)
          │
         ДА
          │
    перевыпускаем под свой CA → браузер доверяет ✓
```

Если Минцифры выпустит сертификат для Telegram — браузер его отклонит, потому что Минцифры нет в системном хранилище.

### Пиннинг сертификатов в приложениях

Некоторые приложения используют **certificate pinning** — не доверяют системному CA, а сравнивают сертификат сервера с захардкоженным внутри приложения. Для них прокси ничего не сломает и ничего не починит: они просто работают напрямую мимо любого CA.

Важнее другое: если такое приложение попадает в whitelist и прокси перевыпустит его сертификат — приложение откажется подключаться, потому что получит «не тот» сертификат. Симптом: приложение перестало работать после настройки прокси.

**Решение:** не добавлять в whitelist домены, которые используют пиннинг. Браузеры пиннинг не используют — для них прокси работает корректно.

## Быстрый старт (Docker)

### 1. Клонировать и запустить

```bash
git clone git@github.com:FlyInk13/resign-proxy.git
cd resign-proxy
docker compose up -d
```

При первом запуске прокси автоматически генерирует CA-сертификат в папку `./data/ca/`.

### 2. Получить CA-сертификат

```bash
# Файл для установки на устройства
ls ./data/ca/ca.crt
```

### 3. Настроить белый список

Отредактируйте `data/whitelist.txt` — по одному домену на строку, поддомены подхватываются автоматически:

```
# Сбербанк (подтверждён)
sberbank.ru

# Добавляйте домены после проверки CA (см. команду ниже)
```

Проверить, использует ли домен Минцифры CA:

```bash
openssl s_client -connect sberbank.ru:443 2>/dev/null | openssl x509 -noout -issuer
# issuer=C=RU, O=The Ministry of Digital Development and Communications, CN=Russian Trusted Sub CA
```

После изменения списка перезапустите прокси:

```bash
docker compose restart
```

## Установка CA-сертификата

Сертификат нужно установить **один раз** на каждое устройство, которое будет использовать прокси.

### macOS

```bash
# Установить в системное хранилище и сразу доверять
sudo security add-trusted-cert \
  -d -r trustRoot \
  -p ssl \
  -k /Library/Keychains/System.keychain \
  ./data/ca/ca.crt
```

Флаг `-p ssl` ограничивает доверие только HTTPS — CA не получит права подписывать код, почту и т.д.

**Если устанавливать через Связку ключей вручную:**

Двойной клик на `data/ca/ca.crt` → открыть сертификат в Связке ключей → раскрыть раздел **Доверие (Trust)**:

| Политика | Значение |
|---|---|
| **Secure Sockets Layer (SSL)** | **Always Trust** |
| Secure Mail (S/MIME) | Use System Defaults |
| Extensible Authentication (EAP) | Use System Defaults |
| IP Security (IPSec) | Use System Defaults |
| Code Signing | Use System Defaults |
| Time Stamping | Use System Defaults |
| X.509 Basic Policy | Use System Defaults |

Только SSL — этого достаточно для HTTPS, и CA не сможет подписывать приложения или письма.

Проверить:

```bash
security find-certificate -c "Ministry of Degradation and Memes" /Library/Keychains/System.keychain
```

Удалить при необходимости:

```bash
sudo security delete-certificate -c "Ministry of Degradation and Memes" /Library/Keychains/System.keychain
```

### iOS / iPadOS

1. Скопировать `data/ca/ca.crt` на iPhone — через AirDrop, email или веб-сервер.
2. При открытии файла появится: **«Профиль загружен»** → нажать **Закрыть**.
3. Перейти: **Настройки → Основные → VPN и управление устройством** → найти профиль → **Установить**.
4. Перейти: **Настройки → Основные → Доверие сертификатам** → включить переключатель напротив «Ministry of Degradation and Memes».

> Шаг 4 обязателен — без него сертификат установлен, но не доверен.

### Android

Путь зависит от версии, общий вариант:

**Настройки → Безопасность → Дополнительно → Шифрование и учётные данные → Установить сертификат → CA-сертификат**

Выбрать файл `ca.crt`. Android предупредит, что сетевой трафик может отслеживаться — это ожидаемо.

> На Android 7+ приложения могут игнорировать пользовательские CA. Браузеры (Chrome, Firefox) подхватывают системный CA корректно.

### Windows

```powershell
# PowerShell от администратора
Import-Certificate -FilePath .\data\ca\ca.crt -CertStoreLocation Cert:\LocalMachine\Root
```

Или вручную:

1. Двойной клик на `data\ca\ca.crt` → **Установить сертификат**.
2. Расположение: **Локальный компьютер** → **Далее**.
3. **Поместить все сертификаты в следующее хранилище** → **Обзор** → **Доверенные корневые центры сертификации**.
4. **Готово**.

### Linux (Debian / Ubuntu)

```bash
sudo cp ./data/ca/ca.crt /usr/local/share/ca-certificates/personal-proxy-ca.crt
sudo update-ca-certificates
```

### Linux (Fedora / RHEL)

```bash
sudo cp ./data/ca/ca.crt /etc/pki/ca-trust/source/anchors/personal-proxy-ca.crt
sudo update-ca-trust
```

### Firefox (отдельно от системного хранилища)

Firefox использует собственное хранилище:

1. **Настройки → Конфиденциальность и защита → Просмотр сертификатов**.
2. Вкладка **Центры сертификации** → **Импортировать**.
3. Выбрать `data/ca/ca.crt` → отметить **Доверять при идентификации сайтов**.

## Настройка прокси на устройствах

Прокси принимает подключения на порту `8080` (HTTPS CONNECT).

### macOS

**Системные настройки → Сеть → [ваш интерфейс] → Прокси-серверы**

- Включить **Безопасный веб-прокси (HTTPS)**
- Сервер: `<IP-машины-с-прокси>`, Порт: `8080`

Или через командную строку (для Wi-Fi):

```bash
networksetup -setsecurewebproxy Wi-Fi <IP> 8080
networksetup -setsecurewebproxystate Wi-Fi on
```

Отключить:

```bash
networksetup -setsecurewebproxystate Wi-Fi off
```

### iOS / iPadOS

**Настройки → Wi-Fi → [ваша сеть] → Настроить прокси → Вручную**

- Сервер: `<IP>`
- Порт: `8080`

### Android

**Настройки → Wi-Fi → [ваша сеть] (долгое нажатие) → Изменить → Дополнительные параметры → Прокси: Вручную**

- Хост: `<IP>`
- Порт: `8080`

### Windows / Linux (системный)

Выставить переменные окружения или системный HTTP/HTTPS прокси на `http://<IP>:8080`.

## Запуск без Docker

```bash
bun install
bun run start
```

Переменные окружения:

| Переменная     | По умолчанию    | Описание                          |
|----------------|-----------------|-----------------------------------|
| `PORT`         | `8080`          | Порт прокси                       |
| `CA_DIR`       | `./data/ca`          | Папка для CA-ключа и сертификата  |
| `WHITELIST_PATH` | `./data/whitelist.txt` | Путь к файлу белого списка    |

```bash
PORT=9090 CA_DIR=/etc/proxy/ca WHITELIST_PATH=/etc/proxy/whitelist.txt bun run start
```

## Структура проекта

```
src/
  index.ts          — точка входа
  proxy.ts          — HTTP CONNECT прокси
  inspector.ts      — инспекция TLS-цепочки upstream
  cert-manager.ts   — генерация CA и листовых сертификатов, кеш
  whitelist.ts      — загрузка и проверка белого списка
data/
  whitelist.txt     — домены с Минцифры CA
  ca/               — генерируется автоматически, не коммитить
    ca.key          — приватный ключ CA (беречь)
    ca.crt          — корневой сертификат (ставить на устройства)
```

> `data/ca/ca.key` — приватный ключ. Тот, кто им владеет, может подписать сертификат для любого домена. Не публиковать, не коммитить, хранить только на машине с прокси.
